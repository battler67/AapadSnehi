# AapadSnehi disaster research

This directory is deliberately separate from the public prototype. Its models are
research artifacts and cannot publish or dispatch warnings.

## Owner and portal handoff

- [OWNER_INTEGRATION_HANDOFF.md](OWNER_INTEGRATION_HANDOFF.md): publication status,
  exact artifacts to transfer, verification and proposed portal integration.
- [MODEL_USER_GUIDE.md](MODEL_USER_GUIDE.md): real-input examples, schemas, units,
  adapter calls and output interpretation.
- [expressitvity.md](expressitvity.md): model capacity, evidence, limitations and
  safe language for presenting predictions.
- `reports/model_handoff_manifest.json`: artifact hashes and exact saved schemas;
  generated by `python -m disaster_research.export_handoff` without uploading weights.

Model binaries are NOT included in Git. A fresh clone's historical completed
ledgers do not prove that its ignored data/checkpoints exist; read the handoff's
clone-versus-resume warning before reproducing experiments.

Start with `UNDERSTAND_THE_PIPELINE.md`. Commands are run from the repository root:

```powershell
.\.venv\Scripts\python.exe -m pip install -r disaster_research\requirements.txt
.\.venv\Scripts\python.exe -m disaster_research hardware
.\.venv\Scripts\python.exe -m disaster_research acquire --dataset all
.\.venv\Scripts\python.exe -m disaster_research status
```

Downloaded datasets, processed tables, runs, and model artifacts are ignored by
Git. Small manifests, audit reports, configurations, tests, and final reports are
retained with the source. Acquisition reuses verified downloads. The execution
drivers reuse completed runs; individual finalist commands may retrain. Resume
checkpoints require the same configuration and prepared dataset. Do not change
features in place and then reuse old run directories.

The pipeline never trains on synthetic data. Unit tests may create explicitly
labelled synthetic fixtures in temporary directories.

## Execution order

After acquisition, run `audit-flood`, `prepare-flood`, `audit-wildfire`,
`prepare-wildfire`, and `screen-wildfire`. Then run the two sequential drivers:

```powershell
.\.venv\Scripts\python.exe -m disaster_research.execute
.\.venv\Scripts\python.exe -m disaster_research.finish
```

Run the second only after the first has exited. Logs and exact commands are under
`runs/execution_v2/`, `runs/finishing/`, `reports/execution_v2.json`, and
`reports/finishing_execution.json`. `FINAL_REPORT.md` is generated from measured
files and explicitly identifies missing results. The initial flood protocol is
superseded and its earlier test inspection is disclosed.

## Where to look

| Purpose | Modules / outputs |
|---|---|
| Hardware and reproducibility | hardware.py, environment.py, monitor.py |
| Acquisition and provenance | acquire.py, reports/acquisition_manifest.json |
| Dataset and timing audits | flood_data.py, landslide_data.py, wildfire_data.py, documentation_audit.py |
| Classical model configurations | model_registry.py, configs/protocol_v2.json |
| Temporal and spatial networks | flood_dl.py, wildfire_dl.py |
| Frozen finalist comparisons | flood_finalize.py, wildfire_finalize.py, flood_analysis.py |
| Historical illustrations | replay.py, reports/*hydrographs.png, reports/*replay*.png |
| Research inference | inference.py; engineered feature rows or daily DL history |
| Student explanation and results | UNDERSTAND_THE_PIPELINE.md, FINAL_REPORT.md |

Artifacts named `xgboost_*` are legacy internal filenames and may contain another
validation-selected estimator. Use `selected_regression.joblib`,
`selected_event.joblib`, and `selected_pixel.joblib` after registry finalization;
the artifact's model_version and report configuration identify the actual model.
